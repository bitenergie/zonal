# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Blender add-on/extension that exports the scene to an OpenStudio `.osm`. It is the **inverse of OpenStudio's glTF forward translator**: `reference/openstudio_gltf/` is a copy of OpenStudio's `src/gltf` C++ source (model → glTF) plus `schemas/*.extras.schema.json`. That source is the spec for the custom-property schema (`extras`); the add-on reads the Blender scene with those properties and rebuilds the model. Don't try to compile or edit `reference/` (local-only, git-ignored).

## Commands

```
uv sync                                   # Python 3.13 venv (openstudio 3.11.0 wheel)
uv run pytest -q                          # unit tests (no Blender needed)
uv run pytest -q -k adjacent              # single test
uv run ruff check .
uv run python scripts/build.py            # fetch wheels + build dist/zonal-<ver>.zip (uses Blender 5.x)
uv run python scripts/build.py --install  # ...and install into Blender's user_default repo

# headless end-to-end export (paths must be Windows-style)
blender -b --factory-startup --python tests/blender_smoke.py -- C:\path\out.osm               # Blender 5.x, uses .venv openstudio
```

`tests/blender_installed.py` verifies the zip's bundled wheel; run it with `BLENDER_USER_RESOURCES` pointing at a scratch dir so the real Blender profile is untouched.

## Architecture

Pipeline (`blender_ui.EXPORT_SCENE_OT_openstudio_osm`): `blender_scene.collect_scene` reads the evaluated Blender meshes + custom properties directly into `Face`s (no glTF file) → `osm_builder.build_model` (OpenStudio API) → `.osm` (`osm_builder.scene_to_osm`). glTF is a **standalone** feature: operators `export_scene.openstudio_gltf` (Blender's glTF exporter with extras) and `import_scene.openstudio_gltf` (`gltf_reader.read_gltf` → `blender_ui.gltf_items` → `build_scene`); `osm_builder.gltf_to_osm/gltf_to_gbxml` convert a glTF file without Blender.

- `core/` (`geometry.py`, `gltf_reader.py`, `schema.py`, ...) does not import openstudio at module level, and bpy-free is **not** a hard rule: use numpy (a dependency) and, where it is faster, `mathutils` (KDTree/BVHTree) and other bpy APIs. Vectorise hot loops (see `tools_geometry.OverlapIndex`, `geometry.cluster_coplanar`). `openstudio` is imported lazily (`openstudio_env.load`); the bindings always run in-process (no CLI subprocess backend).
- Meshes are triangulated (`loop_triangles`, like glTF) and `geometry.faces_from_triangles` welds vertices, clusters edge-connected coplanar triangles, traces the outer boundary loop (largest area; holes are dropped because OpenStudio models openings as separate sub-surface nodes) and drops collinear points. One Blender mesh with several faces therefore yields several surfaces (`name 1`, `name 2`, …) and the `surfaceType` extra is ignored for base types on multi-face meshes (classified by tilt instead).
- **A surface's space = its (original) collection**; space attributes (space type, zone, story, unit, construction set) live on the Space (`Scene.osm_model` item, one value per space) and never per surface: `osm_<key>` proxies read/write the store, `inspector.get_space_attr/set_space_attr`. Legacy per-surface values are only a fallback in the export (`ui.default_space_overrides`, one forced value per space + conflict warnings); `scene.osm_migrate_spaces` moves them to the store. Imports (`ui.build_scene`) write them to the store. The standalone glTF export temporarily writes them on the objects.
- Per-node data comes from the node's `extras` (Blender custom properties on the object) using the OpenStudio schema keys (`surfaceType`, `spaceName`, `thermalZoneName`, `outsideBoundaryCondition`, …). Merge order, lowest to highest priority: operator defaults (`spaceName` = collection name) < mesh extras < node extras. Scene custom props → scene extras (`northAxis`, `modelObjectMetaData` for story/zone colours, nominal heights, multiplier).
- `osm_builder._Builder.run` order matters: base surfaces → sub-surfaces (parent by `surfaceName`, else geometric containment) → shading / partitions → adjacency (`Surface` boundary condition resolved by name after all surfaces exist). Boundary condition must be set before sun/wind exposure.
- gbXML: no separate pipeline, it goes through the OpenStudio model. Export = same direct scene → `build_model` → `osm_builder.scene_to_gbxml` (`GbXMLForwardTranslator`). Import = `osm_reader.read_gbxml` (`GbXMLReverseTranslator.loadModel` → shared `read_model`) → same mesh builder. Operators `export_scene/import_scene.openstudio_gbxml` share `_ExportOptions`/`_ImportOptions` mixins with the .osm ones in `blender_ui.py`. Tests: `tests/test_gbxml.py`, `tests/blender_gbxml_smoke.py -- <in.xml> <out.xml>`.
- Files from OpenStudio itself (generator `OpenStudio`) are Y-up behind a `Z_UP` root node; `read_gltf` auto-converts. Blender output is exported Z-up so no conversion.

## Environment gotchas

- **Blender 5.0+ only; do not write or keep compatibility code for Blender < 5** (manifest `blender_version_min = "5.0.0"`; use `layout.panel()`, slotted/layered actions and the 5.x node-modifier API directly). Blender 5.x = CPython 3.13 (cp313) = the dev `.venv`, so the bundled wheel and `.venv` openstudio match. Another OpenStudio install can be set in the pref `openstudio_path` (`<root>/Python` + `<root>/bin`, resolved by the bpy-free `openstudio_env.py`) if its CPython matches; `_openstudio*.pyd` fail with "DLL load failed" on a mismatched version.
- `pyproject.toml` has `tool.uv.required-environments` (Windows only) — without it uv can't resolve the Windows wheels of `openstudio`.
- Blender 5.x offers only `GLB`/`GLTF_SEPARATE` export formats (no `GLTF_EMBEDDED`).
- Every `blender_*.py` module imports `bpy`; `__init__` imports `blender_ui` lazily so the package stays importable in pytest. Performance beats bpy-freedom: pick the fastest approach (numpy, `foreach_get`, mathutils) even in `core/`.
- `OpenStudio` `Space.transformation()` caches the first value it returns: don't call it before setting origin / relative north (see `osm_builder.apply_space_transform`).
- `.mcp.json` registers the `blender-mcp` server (`uvx blender-mcp`); it needs the BlenderMCP add-on connected inside Blender (port 9876).
- Downloaded wheels live in `src/zonal/wheels/` (git-ignored, ~100 MB); `scripts/fetch_wheels.py` recreates them.

## Modeling tools (UI side)

- `blender_tools.py` (draw tool, separate faces, sidebar), `blender_props.py` (dropdown/search proxies `osm_<key>` on Object that read/write the real custom props, name library `scene.osm_library`, .osm template), `blender_surface_ops.py` (surface matching, loose geometry). All registered from `blender_tools.register()`.
- Pure logic lives in `tools_core.py` / `tools_geometry.py` (tested in `tests/test_tools_core.py`).
- Template: `BuildOptions.template_osm` clones the template model and strips spaces/zones/stories/etc., keeping space types, construction sets, constructions (+materials, schedules). `templates/MinimalTemplate.osm` is the bundled default.
- Meshes in the collection `OpenStudio - Loose Geometry` are never exported; `object.osm_project_loose` turns their faces into sub surfaces.
- Surface Search panel: `blender_search.py` (Scene.osm_search, operators select matching objects) over the pure `search_core.py` (azimuth with north axis, wrap-around ranges, non-convex test, `matches`).
- OpenStudio Inspector panel: `blender_inspector.py` over the pure field table `inspector_schema.py`. Object-backed types (Surface, SubSurface, ShadingSurface, InteriorPartitionSurface) edit object custom props via the `osm_<key>` proxies. Store-backed types (Building, Space, ThermalZone, BuildingStory, BuildingUnit, SpaceType, Default*Set/Constructions) live in `Scene.osm_model`; the export operator writes them as scene extra `osmModel` (JSON), `osm_builder.apply_store_resources/apply_store_spaces` applies them via the `FieldDef.setter` names. Store wins over per-surface extras; defaults are not exported. Add a type/field = one entry in `inspector_schema.TYPES` (a test checks the setter exists in OpenStudio). Not yet covered: Facility, Daylighting:Control, Glare:Sensor, IlluminanceMap, ShadingControl, FrameAndDivider, Rendering:Color.
- Headless checks: `tests/blender_tools_smoke.py`, `tests/blender_features_smoke.py -- <out.osm>`, `tests/blender_inspector_smoke.py -- <out.osm>` (Blender 5.x).
- Results panel: `blender_results.py` over the pure `results_core.py` (`SqlResults` wraps `openstudio.SqlFile`; `list(ts.values())` segfaults, index it). Keyframes a float custom prop `osm_result` on surfaces (key = object name) / zones (key = `thermalZoneName` or space/collection), shared heatmap material via an Attribute node, labels = Geometry Nodes group `OSM_ValueLabel` with a keyframed Value input (animates and renders, no handler). Node-modifier inputs are `mod.properties.inputs.<id>.value` (helpers `_set_input`/`_input_path`); actions use the 5.x channelbag API (`_fcurves`). Test: `tests/test_results_core.py` (sample .sql via `OSM_SAMPLE_SQL`), `tests/blender_results_smoke.py -- <eplusout.sql>`.
- Scripts panel: `blender_scripts.py` (panel `VIEW3D_PT_osm_scripts`, `Scene.osm_scripts`, operators `scene.osm_run_script` / `scene.osm_scripts_refresh`) over the bpy-free `scripts_core.py` (`ArgDef`, `UserScript`, `ScriptContext`, registry). Python ports of the SketchUp-plugin Ruby scripts in `reference/user_scripts/` (no Ruby/CLI) live in `user_scripts/<group>/*.py`, one `@register`ed `UserScript` subclass each; `discover()` imports them. Category = the original folder name, args = the Ruby `arguments(model)` (labels/defaults copied 1:1). Panel: category dropdown, script dropdown (only when >1), variables, input (scene or .osm), result (replace scene objects via `read_model`+`build_scene`, or save .osm), Run. `runner.inSelection` -> `ctx.in_selection` (selected objects, plus spaces whose objects are all selected), `yesNoPrompt` -> `confirm_message` (Blender confirm dialog), `creates_geometry` scripts run on an empty model and are added as a new collection, `modifies_model=False` for reports. All 39 originals are ported. Extra `UserScript` flags: `viewport` (Visualization: the script fills `ctx.show_spaces/hide_spaces/view_layers`, the operator hides objects / creates view layers; scene input only), `reads_scene=False` (runs on an empty model), `edits_geometry=False` (result not re-imported), `produces_template` (wizard: model saved as `<blend>_template.osm` -> `scene.osm_template_path`), `ctx.weather_file` / `ctx.building_defaults` (set in the Inspector store). BCL weather needs the manifest `network` permission. The wizard data (`user_scripts/templates/resources/`) is a copy of the Ruby resources. Tests: `tests/test_scripts_core.py`, `tests/blender_scripts_smoke.py -- <out.osm>` (Blender 5.x).

## Plugin-parity additions (from the SketchUp-plugin comparison)

- File layout: the Blender modules named `blender_*.py` above live in `src/zonal/blender/` without the prefix (`blender/ui.py`, `scene.py`, `tools.py`, `props.py`, `surface_ops.py`, `search.py`, `inspector.py`, `results.py`, `scripts.py`); pure logic in `core/`.
- `osm_builder` repairs geometry like the plugin's `check_model_object`: `sanitize` (drop < 3 vertices, project out-of-plane vertices), `orient` (upside-down Floor / RoofCeiling are reversed), `locate_parent` / `conform_to_parent` (sub surfaces: strict match first, then relaxed: flipped and/or within 5 cm of the base plane are fixed; a sub surface as big as its base is skipped), `check_adjacency` (every `Surface` boundary needs a partner that points back). Each repair adds a `BuildReport` warning. `finalize_zones` (after the store): `BuildOptions.new_zone_for_space` (pref `new_zone_for_space`) gives zone-less spaces a thermal zone, every zone gets a default `RenderingColor`; `sync_site` copies the WeatherFile city/lat/lon/time zone/elevation to the Site (OpenStudio's WeatherFile setters don't); `check_sub_adjacency` mirrors `check_adjacency` for sub surfaces. Sub surfaces are rejected like the plugin does: `contained` (also for an explicit `surfaceName`) and `dividing` (an edge-to-edge strip splits its wall into several base surfaces; warning names them).
- Partial import = templates: `BuildOptions.template_osm` (+ `template_types`) is the main template, `extra_templates` = `[(path, [types])]` merges only the chosen categories (`SpaceType`, `DefaultConstructionSet`, `Construction`, `Schedule`; `Schedule` keeps unreferenced schedules) of more files via `ModelObject.clone(model)` (first file wins on name clashes). Scene property `osm_extra_templates` is JSON (`tools_core.encode/decode_extra_templates`); operator `scene.osm_import_resources`. An `.idf` template is translated first (`osm_reader.idf_to_osm_file`, cached in the temp dir).
- SDD: `osm_builder.scene_to_sdd` / `osm_reader.read_sdd`, operators `export_scene/import_scene.openstudio_sdd`. OpenStudio 3.11's SDD forward translator crashes on an empty `OS:ClimateZones` (removed before writing) and its reverse translator cannot read the "Input" SDD it writes itself (only result SDDs). IDF export has `untranslated` (`scene_to_idf_untranslated`, OS: objects as IDF text).
- `blender/modeling.py`: Create Spaces From Diagram (`core/diagram_core.py`), Create Spaces From Mesh (`object.osm_spaces_from_mesh`, `core/volume_core.py`: welds, splits coplanar partial overlaps / T junctions, then finds enclosed cells by sorting faces around each edge and union-finding face sides; one collection per cell, outward faces, optional `mesh.intersect` first, then Intersect + Match, stories by lowest z), Set Attributes for Selected Spaces, Set as Shading / Interior Partition, Info Tool (`core/info_core.py`, modal hover overlay). Intersect = `object.osm_match_surfaces(mode="INTERSECT")` (`tools_geometry.cut_polygon_by_polygon` cuts a surface where another passes completely through it, then the same overlap split as Match, no boundary conditions).
- Surface Search extras: tilt range, building story (Inspector store wins), invert / invert across classes (`search_core.matches`), Hide Everything Else + Unhide All, View Layer From Result.
- Preferences (`OSMPreferences`): `show_warnings`, `new_zone_for_space`, `disable_user_scripts`, `unit_system` (switches the scene's display units). `ui.report_messages` keeps every warning in `ui.LAST_MESSAGES` for `scene.osm_show_warnings` (also writes the text `OpenStudio Report`).
- Not covered on purpose: Daylighting Control / Glare Sensor / Luminaire / Illuminance Map, "last import dir" preferences, SketchUp-only view tools. Not yet run: the new operators in a real viewport session and headless smoke scripts for diagram / intersect / SDD (covered by in-process `bpy` tests: `tests/test_blender_modeling.py`, `test_blender_surface_ops.py`, `test_sdd.py`).

## UI redesign additions (Blender-native widgets)

- `blender/widgets.py`: shared draw helpers (`draw_range`, `draw_enum_row`, `split_column`).
- No Python tree-view API exists in Blender 5.x. The Inspector "Hierarchy" picker is a `UIList` (`OSM_UL_inspector_tree`) over a flat `OSMTreeRow` collection (`Scene.osm_inspector.tree`); collapse is done in `filter_items`; pure logic in `core/inspector_tree.py`. Rebuilt by `scene.osm_tree_refresh` and by the depsgraph handler when the object count changes.
- Inspector field kinds `COLOR` ("#RRGGBB", colour picker + `<key>_set` toggle, setter `setRenderingColor`) and `RULES` (JSON rule list on `ScheduleConstant`, edited in `blender/schedule_ui.py`: `OSMScheduleRule` collection `item.rules` + `OSM_UL_schedule_rules`, list order = priority, per rule hour range + value, weekday toggles, month checkboxes, day-of-month grid, plus a "Dates of the Year" month calendar (weekday aligned, w# buttons toggle a week, `<` `>` navigation). The calendar shows the EFFECTIVE dates = (weekday/month/day pattern - excluded) + included, so it follows the pattern; editing a day stores only the difference as bit masks `inc_MM`/`exc_MM` (custom props on the rule; the `dates_01..dates_12` BoolVectors have get/set callbacks because Blender arrays hold max 32 items; Reset = back to the pattern). Calendar/grids use `_plain()` (no property split) and one aligned column so cells touch like Blender's calendar example; pure logic in `core/schedule_rules.py`). The builder (`osm_builder.rules_schedule`) makes a `ScheduleRuleset` (default day = `scheduleValue`; first list item = ScheduleRule index 0; month runs -> date range + weekday flags, partial days-of-month -> specific dates, weekday-filtered for the assumed year 2009). Reading an existing ScheduleRuleset back into rules is not implemented.
- Render modes: `tools.draw_render_modes` (panel + shading popover) with an editable legend (`Scene.osm_legend`, user overrides in `Scene.osm_color_overrides`). Library = one `UIList` + Kind dropdown. Results heatmap has `template_color_ramp` + presets. Pie menu `VIEW3D_MT_PIE_osm_tools` on Ctrl+Shift+O. Use `layout.panel()` for collapsible groups; fake layouts in tests need a `panel()` returning a tuple.
